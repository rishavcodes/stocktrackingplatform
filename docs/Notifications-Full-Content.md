# In-App Notifications — Full Content Reference

Every in-app notification the Tradebox backend generates, with the exact message string, recipient, type, category, and source location.

> **Scope:** in-app notifications only (the bell/inbox panel inside the app). Email, Telegram, WhatsApp, and SMS are deliberately excluded — see [Notifications-Inventory.md](Notifications-Inventory.md) for those.

## How dispatch works

- Every in-app notification is a document in the `notifications` collection (`models/NotificationModel.ts`) whose `_id` is fanned out into each recipient's `notifications[]` array on `UserModel`, `ServiceProviderRegModel`, or `AdminModel`.
- Most call sites go through [helpers/sendNotification.ts](server/src/helpers/sendNotification.ts), which also emits `notification:new` on the `/notifications` socket namespace per recipient room.
- Wallet credits/debits go through [helpers/Notify.ts](server/src/helpers/Notify.ts) → `notifyWalletChange()` (always `type: "wallet"`, `sentBy: "System"`).
- Admin-broadcast events go through [helpers/Notify.ts](server/src/helpers/Notify.ts) → `adminNotify()` (always `type: "admin"`, recipients = all admins).
- A few older sites create the doc directly with `new notificationModel({ ... })`.
- `<placeholders>` in the message text mark runtime values.

## Notation

- **Type** values are validated against the enum in [NotificationModel.ts](server/src/models/NotificationModel.ts).
- **Category** is `admin` / `sp` / `broker` (defaults to `admin` when not set explicitly).
- **Sent by** is the actor recorded on the doc's `sentBy` field — what the recipient sees as the "from" chip.
- Fields that don't apply on a card show `—`.

## 6. Wallet

All wallet notifications use the helper [helpers/Notify.ts → notifyWalletChange()](server/src/helpers/Notify.ts#L12-L39).

- **Type:** `wallet` (always)
- **Category:** `admin` (default — `notifyWalletChange` does not set it)
- **Sent by:** `system` / `System` (always)
- **Message template:** `"₹<amount> <credited|debited> <to|from> your Tradebox wallet — <reason>. New balance: ₹<newBalance>."`
  - Amount is rounded and formatted in en-IN locale (`₹1,200`).
  - `New balance:` clause only appears when `newBalance` is supplied (every site in this codebase supplies it).

### N14. Wallet debit — onboarding / renewal commission (service order, legacy path)

- **Generated by:** `PaymentController.processPaymentForServiceOrder`

- **Example message:** `"₹354 debited from your Tradebox wallet — onboarding commission for Equity Pro. New balance: ₹4,646."`
- **Source:** [PaymentController.ts:691-701](server/src/controllers/PaymentController.ts#L691-L701)

### Known data-quality observations

- **N2 (Follow)**, **N36 (Event registration to SP)**, **N37 (Event approval)**, **N38 (Service approval)** create the doc without a `type` value — they bypass the enum default and will show with an empty `type` field.
- **N36** uses `ServiceProviderRegModel.updateMany({})` with no filter — every SP receives the notification id, not just the event author. This is a latent bug, not the documented behaviour.
- **N38** message literally says "Posted new event" even though the entity is a service plan — kept verbatim from the source.
- **N24 (wallet low-balance cron)** is registered in code but **paused** per commit `28bac8df` ("low balance email reminder paused"). No reminders are currently dispatched.
